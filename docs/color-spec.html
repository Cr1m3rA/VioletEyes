VioletEyes 配色规范

V1.2-hotfix · 浅色 / 深色 1-to-1 映射 · Tailwind + 自定义 CSS

设计哲学：浅色 / 深色两套配色系统结构平行 —— 每个浅色 token 都有语义等价的深色 token。 浅色用 50-100-200-300-700-900 的暖灰阶；深色用 800-900-950 的冷灰阶 + 950/60 半透明彩色 + 300 高亮文字。 任何元素的设计都先想清楚它属于「背景层 / 表面层 / 边线 / 文字 / 强调」中的哪一层，再用对应的 token。

1. 设计哲学与映射原则

VioletEyes 的双主题不是「同一份 HTML 调换 bg」式的浅翻深，而是两套平行的 token 系统。每层都有明确语义：

10. 打印模式

打印强制使用纯白 / 纯黑，跨主题一致：

@media print {
  body { background: #fff !important; color: #000 !important; font-size: 11pt; }
  header.sticky, footer, .no-print { display: none !important; }
  section, .finding { box-shadow: none !important; break-inside: avoid; }
  a { color: inherit; text-decoration: underline; }
  pre[class*="language-"] { max-height: none !important; overflow: visible !important; }
}

11. 可复用指南

设计新组件时的检查清单

  1. 这个组件属于哪一层？（页面底 / 卡片 / 抬升 / 边线 / 文字）
  2. 如果含彩色信息，属于哪个语义色族？（severity / brand / auxiliary）
  3. 深色版本是否需要提亮 1 档？（如 violet-500/700 → 400/600）
  4. 如果含 bg-{color}-100 / text-{color}-700，深色是否改成 bg-{color}-950/60 / text-{color}-300？
  5. 如果含 bg-{color}-50 / text-{color}-700，深色是否改成 bg-{color}-950/40 / text-{color}-300？
  6. severity 关键元素（accent strip / letter avatar / dot）保持跨主题同档色 —— 深色背景反而更显眼。
  7. 代码块保持 #2d2d2d —— 它本身就是 dark-by-design。
  8. 打印模式强写纯白 / 纯黑，跨主题一致。

反模式（避免）

  • ❌ 在浅色上用 50/700 文字 —— 深色上对比度不够
  • ❌ 把彩色 -100/-50 写死成固定 RGB，没有 dark: 变体
  • ❌ 用 200 边框当卡片底色（太亮）
  • ❌ 代码块用浅色背景（深色背景里的浅色代码块会刺眼）
  • ❌ 严重度色族跨主题用不同饱和度（破坏视觉一致性）
